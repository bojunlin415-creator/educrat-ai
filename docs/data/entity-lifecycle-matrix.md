# Entity Lifecycle Matrix

- 狀態：**Accepted — Architecture Approved**
- Architecture Package：AP-002
- 說明：完整動作矩陣；尚未實作任何 Entity、API、UI 或 Migration

## 圖例

- `A`：允許，但仍需權限、scope、state、dependency 與 Audit。
- `C`：條件式；依 row 內條件與 retention policy。
- `P`：需 Platform review／受控 job。
- `N`：不支援。
- `I`：不可變；只允許附加更正、void/retire/supersede marker。
- 角色：`PSA` Platform Super Admin、`PA` Platform Admin、`OO` Organization Owner、`OA` Organization Admin、`T` Teacher、`R` Reviewer、`Self` 本人、`Svc` 受控 service/job。

Retention 不設定具體天數；`Policy` 代表使用 versioned platform/legal/organization policy。所有 `Permanent Delete` 的 `C/P` 都禁止一般 CRUD 直接執行。

## Permanent Delete Eligibility 補充

- `C` 只表示可能符合，不表示 Organization Owner 可直接執行。
- 有 protected Teaching/Learning/Assessment/Billing/Audit dependency 時，必須改用 archive、retire、void marker、anonymize 或 Platform review。
- Teacher、Reviewer、Student、Parent 不得執行永久刪除 Organization-owned 或 protected records。
- Platform Super Admin 只核准；實際執行由一次性、最小範圍、可稽核的 background job 完成。

## 現況相容

Sprint 8 的 Chapter/Lesson hard delete 與本矩陣的未來規則有治理落差。現階段尚無 protected history tables，因此不回改歷史 Migration；後續 implementation package 必須先建立 dependency-aware lifecycle v2，再安全撤銷舊 RPC 的 authenticated execute。
